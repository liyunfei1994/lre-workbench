# 概念设计与固定硬件稳态：任务、数据接口与迭代框架

当前 Web 平台的设计与研究入口专用于液氧甲烷全流量补燃循环（FFSC）。GG／煤油旧方案及结果保留为只读历史，原字段和底层兼容模型不删除，也不自动转换为 FFSC。新建、修改、导入及运行须满足这一范围；循环与推进剂在设计页作为既定架构显示。

当前已分开任务入口、输入身份和保存记录，并建立待补数据接口与通用迭代框架。尚未接入发动机固定硬件方程和真实部件特性，因此不能生成固定发动机工作点。

## 概念设计输入与本轮求解范围

“设计输入”包括总体要求、方案选择、边界和模型假设。“初选假设”是本轮采用的方案值，部件校核后可修改并重新计算；“数值初值”只用于启动迭代，最终解不必等于初值。确认或保存参数表示本轮采用，不代表工程校核通过。

当前 FFSC 主用路径保留设计点热力匹配：指定预燃室氧燃质量比时，交叉分流由质量守恒和配比关系确定，内层求总质量流量与两侧涡轮压比，以满足目标推力和两侧功率平衡。指定预燃室温度时，另有反求配比的温度外环；历史自由分流模式仍以总流量及两股交叉流量求解。供给压力、热力与冷却关系由代数消元和耦合层处理，不能把三个核心残差误解为全部物理关系。

“泵方案与尺寸初估”中的转速方式是界面适配，不新增计算输入：给定初选转速沿用正的 `*_pump_speed_rpm_override`，按目标比转速估算沿用其值为 `0` 的原约定。两种方式均不通过泵/涡轮特性图求运行转速。虚拟字段 `lox_pump_speed_mode`、`fuel_pump_speed_mode` 不保存到 `EngineInputs`，旧方案与计算默认值保持兼容。

级数是本轮固定的离散方案；压头系数、入口/出口速度系数、轮毂比与轴向比例用于代表级尺寸和流道初估，不作为数值迭代初值。当前效率仍是输入假设，部件几何尚未自动预测效率并反馈循环；FFSC 主轴也没有另建轴承和密封机械损失预算。目标推力命中、数值收敛和功率闭合，均不等同于部件可实现或试验验证。

“涡轮方案与尺寸初估”接收循环计算的流量、焓降和功率需求，采用同轴泵的本轮转速。初选速比 `U/C₀` 按整台涡轮的总等熵焓降定义，用于中径初估，不是优化目标或单级速比。级数可给定，也可沿用现有速比规则估算；估算结果不是最优级数。级数选择虚拟字段 `turb_ox_stage_mode`、`turb_fuel_stage_mode` 仅用于系统设计页面，仍以 `turb_*_n_stages_user=0` 表示按规则估算、正整数表示给定初选级数，不新增 `EngineInputs` 参数。切换为给定级数且无先前正整数时须填写级数，不自动猜值。

反动度和轴向流量系数 `ca/U` 只在启用均径校核时使用，自定义各级比功比例只在自定义分配模式使用；关闭后保留原值。该校核构造速度三角形，不求逐级压力、损失或叶型，也不自动更新涡轮效率。节圆速度参考上限属于校核约束，不是材料许用叶尖速度。状态量约定单独作为模型假设：声明总态接口不执行总静转换、不更改循环数值或历史记录。部件数据导出继续保留接口约定与来源，供后续详细设计使用。

设计流程为：总体输入与假设 → 循环匹配并提出部件需求 → 部件设计与校核 → 根据有依据的部件性能修正效率、压损及初选方案 → 重新匹配循环。当前程序支持保存和重新计算这些修正，尚未建立自动部件特性反馈或固定硬件运行求解，不能用增加转速未知量代替缺少的性能关系。

## 参数名称与旧字段兼容

**氧燃质量比**的完整定义是**氧化剂质量流量除以燃料质量流量**，是无量纲量。旧名称 `MR` 来自英文 *Mixture Ratio*，本项目采用氧化剂在分子、燃料在分母的质量流量口径；它不是体积比、摩尔比或当量比。界面、提示和参数说明优先使用中文名称。

整机氧燃质量比、富氧预燃室氧燃质量比、富燃预燃室氧燃质量比分别对应不同流量范围，不能互相替代。旧数据字段 `of_ratio`、`ox_preburner_mr`、`fuel_preburner_mr` 及带 `_target` 的输入字段保持原名以兼容历史方案和接口；第三方 RocketCEA 要求的 `MR` 参数名也保留。

温度反求结束后，程序恢复输入中的预燃室配比初值；实际结果应读取 `calculation.summary.ox_preburner_mr` 和 `fuel_preburner_mr`。固定硬件任务的命名初值只取这些实际输出，缺少输出时不从恢复后的输入或设计目标补值。

仅关闭温度目标会进入规定配比的概念设计；同时关闭温度和配比目标仍为历史自由分流设计。两者都不构成固定机组匹配。当前没有新增“规定配比的诊断扫描”功能；若以后建立固定来源配比的节流对照，应取来源实际解并明确使用该诊断名称，不能把旧设计匹配扫描或现有预燃室配比设计扫描改名后视作正式固定硬件分析。

保存的概念求解向量新增 `vector_schema`，由 `src/lre_workbench/solvers/state.py` 声明版本、模式、变量全称、顺序与单位。指定配比设计使用总质量流量和两侧涡轮压比；历史自由分流设计使用总质量流量和两股交叉流量。读取旧热启动时必须逐项匹配身份；缺少标记或身份不符时使用原有冷初值，不按相同数组位置猜测或换算含义。原记录保持原样，新计算记录拒绝原因。新固定硬件任务仍只使用白名单中的命名初值，不接收这些概念求解向量。

| 入口 | 数据与行为 | 当前可做 |
| --- | --- | --- |
| 概念设计 | 设计目标、设计选择、边界、模型配置、约束、命名初值、数值设置分别保存；调用原概念设计求解器 | 保存方案、设计计算、查看结果 |
| 固定硬件稳态 | 从指定已完成设计记录读取可冻结的硬件；工况、初值与约束独立保存 | 检查来源与缺项、编辑边界、保存任务、导出待补数据模板、运行独立数值框架自检 |
| 稳态控制配平 | 绑定已保存固定硬件任务，另行定义推力百分比、显式附加目标和操纵量 | 保存配平定义、检查控制数量、运行独立双层代数自检；实际发动机配平尚未开放 |
| 设计匹配扫描（旧） | 保留原节流算法及历史，仍按来源温度/MR目标作设计匹配 | 过渡研究用途，不能作为固定整机的节流能力证明 |

## 使用方式

1. 在“概念设计”完成并保存一个设计结果。
2. 打开“固定硬件稳态”，选择本项目已完成的来源记录。
3. 检查来源版本、硬件指纹、冻结内容和待补能力，编辑该任务的运行边界。
4. 保存任务定义。后续编辑再保存会形成新记录，不修改先前记录；可查看和下载 JSON。
5. 在已保存任务中下载待补数据模板。各字段保持 `null`，补充时需声明来源、版本、摘要、单位和适用范围。
   填写后可在“登记文件校核”选择 JSON 文件（最多 200000 字节），查看缺项与格式校核结果；此操作不保存或采用文件中的硬件声明。
6. “数值框架自检”运行独立无量纲代数算例，显示接受迭代的残差及变量曲线。结果另行保存、可导出，不使用发动机工况，不改变任务可运行状态。
7. 在已保存任务的“稳态控制配平”卡片填写推力百分比。附加 氧燃质量比 或预燃室温度等式目标须显式开启、填写数值和容差；不开启时不继承来源目标。保存生成不可变的配平定义。
8. “双层数值自检”提供目标可达、限位未达、内层失败和控制相关的独立代数场景。曲线和求值记录仅用于检查软件行为，不是该百分比下的发动机结果。

当前不提供固定硬件工作点结果。页面列出缺少的部件数据与模型接口；请求运行返回 HTTP 409，且不会进入概念设计队列。预燃室温度限值可作为独立约束保存，温度设计目标不会自动成为等式目标；新增外层配平定义可另行显式声明温度等式，但仍须满足控制数量、独立性及模型就绪要求。自检通过仅表示该代数算例达到数值阈值，不能代表发动机方程、热力模型或运行约束通过验证。

## 数据契约

`src/lre_workbench/domain/analysis_roles.py` 定义各分析模式的参数用途，供页面、字段说明和固定硬件任务快照使用。固定硬件稳态与控制配平目前仅支持任务配置，尚未开放发动机工作点求解。

| 参数 | 概念设计 | 固定硬件稳态 |
| --- | --- | --- |
| 预燃室出口温度 | 温度目标模式给定出口温度；指定氧燃质量比模式计算出口温度 | 计算输出；温度上限单独作为约束 |
| 预燃室氧燃质量比与交叉分流 | 指定配比模式给定氧燃质量比；温度目标模式以输入配比作初值；历史自由分流模式以交叉分流参数作初值 | 由支路质量流量确定；来源计算结果可用作初值 |
| 泵出口压力 | 主泵按压力预算计算出口压力需求；前置增压泵出口压力为给定设计值 | 由泵特性与系统阻力匹配确定 |
| 泵与涡轮转速 | 泵转速可给定或按比转速估算；同轴涡轮沿用对应泵转速 | 轴系匹配的求解量；当前不支持给定轴转速边界 |
| 涡轮级数 | 给定初选级数或按现有规则估算，不代表最优级数 | 采用已确定的实际结构级数，不能把设计输入的 0 作为硬件级数 |
| 涡轮速比与几何初选假设 | 用于尺寸初估及可选均径校核，不反馈效率 | 仅作为设计依据保留，不能代替部件特性 |
| 涡轮节圆速度参考上限 | 校核约束，不是材料许用叶尖速度 | 保留参考约束，仍需独立结构校核 |
| 阀门尺寸、流量特性与开度限位 | 全流量补燃循环计算支路所需附加节流压降，供阀门选型 | 硬件参数，随硬件定义固定 |
| 阀门开度 | 设计点开度需依据阀门特性确定；当前设计模型未定义开度 | 运行设定或配平调节量，受开度限位约束；当前不接受开度输入 |
| 主燃烧室压力 | 给定设计输入 | 工作点计算输出 |
| 推力 | 给定环境压力下的设计目标 | 工作点计算输出；可在控制配平任务中设为目标 |
| 整机氧燃质量比 | 给定设计输入 | 按整机供给流量计算；可设为附加配平目标 |
| 喷管、冷却通道及喷注器几何 | 设计输入或定尺寸结果 | 工作点计算采用给定几何；热气喷注器流通特性待补 |

固定硬件任务的 `hardware.payload.valves`、`operating_conditions.controls.valve_openings` 和 `operating_conditions.control_targets` 当前均为空对象。推力百分比、容差及整机氧燃质量比和预燃室出口温度的附加目标在独立的控制配平任务中保存。

`src/lre_workbench/domain/analysis_contract.py` 的平台新概念任务采用版本 3，仅保存液氧甲烷 FFSC 参数，移除燃气发生器温度、分流、轴系布局及排气喷管等非 FFSC 字段。平台参数无损分组为 `design_targets`、`design_choices`、`boundaries`、`model_configuration`、`constraints`、`initial_guess`、`solver_settings`。指定预燃室温度时，氧燃质量比为反求初值；指定氧燃质量比时，氧燃质量比为设计输入。预燃室压力比在目标模式为初猜，在历史自由分流模式为设计输入；未启用的 FFSC 目标保留在模型配置中用于兼容。泵转速、几何和材料选型归设计选择，允许上限归约束。

版本 1、2 概念任务继续按原布局严格读取，不改写历史记录；重新执行前仍须通过平台循环与推进剂范围检查。已有 FFSC 输入中的非 FFSC 字段会在创建新任务时清理，有效 FFSC 值保留。各版本均检查模式、缺失、未知、重复及错误分组；分组不改变求解公式。固定硬件任务仍沿用其独立的版本 2 契约。

`webapp/fixed_steady.py` 定义另一套任务：

- `source`：来源计算 ID、方案版本与结果摘要。
- `hardware`：已保存的喷管、供给阻力、冷却几何及材料证据；内容摘要用作指纹。已有证据不等于完整可运行硬件定义。
- `operating_conditions`：边界与控制量分离。尚未定义阀门特性，非空阀位请求会被拒绝。
- `parameter_roles`：保存任务建立时的两类分析参数身份说明。
- `legacy_design_assumptions`：只读保留来源前置增压出口设计要求和短管压降预算，明确 `adopted_as_boundary=false`；两者不进入新运行边界或固定硬件特性。
- `initial_guess`：带固定硬件模式身份的命名量，仅从来源实际输出提取；不继承概念设计的匿名 `x` 向量。
- `constraints`：预燃室和冷却壁温限值及其状态、依据；独立于温度设计目标。
- `readiness`：是否可运行以及具体缺项。即使客户端伪造 `can_run=true`，也不能启动设计计算。
- `model_data`：独立版本的待补数据清单，列明字段、单位、接口约定和仅属设计证据的已保存内容；没有默认特性值。
- `valve_requirements`：选定设计结果的只读阀门需求交接表；不属于已登记阀门硬件。

当前硬件指纹同时绑定来源审计证据（例如冷却沿程证据摘要），用于检查同一来源任务的冻结内容是否一致；它不用于判断两个不同来源设计是否具有完全相同的制造几何。

新任务只接受来源 ID、允许的工况字段及命名初值。客户端不能上传硬件替代品、设计温度/MR目标、定尺寸开关或匿名求解向量。调整工况和初值不改变硬件内容与指纹；更换硬件必须选择另一份来源。

版本 2 固定任务的可编辑边界只有环境压力、贮箱压力、燃料入口温度和氧化剂入口温度。保存的版本 1 固定任务仍原样查看和导出，页面明确提示其中旧供给预算字段不作为新版边界；不会原地迁移历史任务。

## 保存与兼容

新概念设计作业增加 `analysis_task`，保留原 `inputs` 适配现有结果消费方。旧方案提交时按已有兼容规则补齐并显式保存参数；旧方案本身不改写。工作进程验证两份输入一致后才运行。历史作业没有新字段时按原概念设计快照读取，历史结果不会被重算或迁移成固定硬件结果。

固定硬件任务保存在独立的 `fixed_steady_tasks` 表；无更新接口，不混入待运行作业。数据库采用增量建表及可重复执行的字段迁移。私有工作区仍按项目所有权限制访问。

新增数据接口是版本 2 任务中的可选扩展，扩展本身含 `schema_version=1`。历史任务不补写这些字段；未含接口的历史任务须从原设计记录另建新任务后导出数据模板。

## 待补数据接口

`webapp/steady_model_contract.py` 登记泵、涡轮、阀门、供给管路、喷注器、轴系、物性、燃烧混合、冷却、喷管和运行约束 11 类需求。数据内容不在本阶段生成。已有几何和单点阻力证据明确标为 `design_evidence_only`，不能被视为部件模型已完备。

登记包绑定任务 ID、完整任务摘要、硬件摘要和来源结果摘要。每项包含修订版本、来源引用与 SHA-256、适用范围及字段。字段类型为文本说明或引用 `{reference, sha256}`，引用是待交接的资料标识，服务不读取本机路径、不请求 URL、不执行公式。表格引用标记 `SI` 仅表示需采用显式单位，后续适配器仍需核对每列单位、定义和数值。

对于 `/api/projects/{project_id}/fixed-steady/tasks/{task_id}`：

| 路径与方法 | 作用 |
| --- | --- |
| `GET /data-template` | 下载与保存任务绑定的空数据登记模板 |
| `POST /data-check` | 校核登记包结构、单位标签、引用摘要格式和缺失字段；不保存或采用输入 |
| `POST /framework-checks`，正文 `{}` | 运行服务器内置的有界无量纲算例，另存诊断记录 |
| `GET /framework-checks` | 读取该任务的自检记录，最新在前 |
| `GET /framework-checks/download?check_id=…` | 下载指定自检及其完整轨迹 |

`data-check` 的 `valid=true` 只表示登记格式有效。`complete=true` 只表示声明字段非空；仍返回 `status=declared_unverified`、`can_run=false`、`adopted=false`。它不验证资料摘要是否与文件内容相符、不确认实际工作域，也不修改保存的任务或硬件。

## 迭代接口与曲线

`src/lre_workbench/solvers/iteration.py` 通过命名变量、上下界、变量尺度和命名残差规格包装已有 `solve_nonlinear`。服务器定义的模型实现 `evaluate(named_state)`，返回完整命名残差与 JSON 输出；变量/残差缺失、重复、非有限、初值越界及错误类型被拒绝。方程数与未知量数相等只是接口前置条件，不证明独立性或物理闭合。

每个残差规格包含单位、尺度和独立容差。轨迹同时记录原始残差、按尺度归一化的残差和按验收阈值归一化的残差。曲线中的阈值为 1；所有分量满足阈值才算数值通过。图上只画初始点和接受步，雅可比探针及拒绝步计入求值次数，不伪装成收敛迭代。未收敛时保留可用轨迹与原因，取消信号仍向调用方传播。

内置自检求解无量纲系统 `x²+y=5, y²+x=3`，使用正边界，校验根为 `(2,1)`。它只测试软件数值链路，不含发动机物理模型。报告的 `analysis_type=numerical_framework_check`、`scope=numerical_framework_only`、`is_engine_result=false` 和 `context.engine_inputs_used=false` 明确身份。自检记录位于独立 `fixed_steady_framework_checks` 表，不写入发动机作业队列，也不更新硬件或工况。

## 概念设计的阀门需求交接

`webapp/valve_requirements.py` 从所选已保存结果读取四条供给支路的流量、取流点/目的地压力、管路/喷注压降与额外节流需求。每个量保留来源路径、单位和缺失原因。取流点温度、密度、焓读取同一已保存状态；供给末端温度单列，避免混淆两处状态。

这个表不反推阀门尺寸、Cv 或开度。原模型管路损失可能已包含全开阀损失，额外节流为零也不表示不需要阀门。实际阀门 ID、安装位置、开度特性、限位、泄漏和材料适用条件保持待补。历史设计结果在读取时生成派生视图，原始计算结果不改写。

## 外层稳态控制配平

`webapp/control_trim.py` 单独定义 `fixed_hardware_steady_trim` 任务。它绑定不可变固定任务、硬件摘要和来源结果摘要，不向固定工况任务写入等式目标，也不调用旧设计匹配扫描。百分比乘以保存的 `calculation.summary.thrust_N` 得到目标定义值；没有此输出时保持缺失，不能回退到输入的设计推力。该参考点仍需固定硬件模型复核，页面同时展示原计算环境压力。

推力相对容差独立保存，默认 0.001，属于数值验收设置而非工程精度保证。附加的整机 氧燃质量比、两个预燃室出口温度目标必须逐一显式提供数值和绝对容差。温度上限继续作为原固定任务约束保存。当前未登记可用阀门，因此操纵量目录为空，非空阀位请求会被拒绝；支路 ID、设计压降预算和填满的资料声明都不能代替已验证阀门。

`src/lre_workbench/systems/control_trim.py` 提供与发动机无关的服务器端数值适配接口 `solve_trim(model)`。每次外层求值只改变明确有界的 `ControlSpec`，调用 `solve_inner(controls)`；仅接受收敛、模型与适用域检查通过、归一化残差不超过 1 的内层结果。`TargetSpec` 独立定义输出目标与绝对容差。控制范围和目标容差用于缩放灵敏度，局部差分 SVD 检查行秩。目标数不超过控制数是必要条件，满行秩也只说明局部数值独立性，不证明全局可达或唯一解。

外层初始点和接受步保存到 `points`；所有内层初值求解、差分探针、试探与失败调用保存到 `evaluations`，逐项包含控制值和内层轨迹。内层失败立即停止外层，不用前一工作点的输出填充失败结果。最后有效接受点单列保留。该接口只验证传入模型的数值行为，不提供或验证发动机模型。

| 状态 | 含义 |
| --- | --- |
| `blocked` | 资料/模型未就绪、控制数量不足或局部独立性不足；不作物理无解判断 |
| `converged` | 当前数值模型内层有效、所有等式目标满足容差；不等于工程验证通过 |
| `target_not_met` | 限位处的本次局部搜索未满足目标，未取得全域不可达证据 |
| `target_unreachable` | 存在单列的适用域内不可达证据；当前仅用于有解析全域界限的代数自检 |
| `numerical_failure` | 内层失败、外层迭代/调用次数耗尽、线搜索或灵敏度计算失败；不是物理无解 |

双层自检的 `u_a,u_b,x,y` 都是无量纲代数量，不映射到发动机阀门、推力、氧燃质量比 或温度。四个固定场景验证可达目标、解析边界外的目标、注入的内层失败、相关控制响应。报告身份为 `analysis_type=control_trim_framework_check`、`scope=numerical_framework_only`、`is_engine_result=false`；不读取当前配平目标、硬件或工况。

以下路径接在已保存固定任务的 `/trim` 后：

| 方法与路径 | 作用 |
| --- | --- |
| `GET /setup` | 读取百分比基准、操纵量目录及阻塞项 |
| `GET/POST /definitions` | 读取/保存不可变的配平定义 |
| `GET /definitions/download?trim_id=…` | 导出指定定义 |
| `POST /run?trim_id=…` | 当前始终返回 HTTP 409 和结构化阻塞原因，不派发引擎作业 |
| `GET/POST /checks` | 读取/运行独立双层数值自检；正文仅含固定 `scenario` 枚举 |

定义和自检分别保存到 `fixed_steady_trim_definitions`、`fixed_steady_trim_checks`，不改写固定任务、概念结果或旧扫描历史。不提供 PID 或瞬态控制器。

## 稳态数值方法与失败诊断

概念设计的“数值求解”中可以选择缩放牛顿法、带重建的 Broyden 方法或有界信赖域对照方法。默认仍为牛顿法。它们求解相同的代数残差；本次变化不引入瞬态积分，也不补造泵、涡轮和阀门特性。

牛顿法每轮建立有限差分雅可比；Broyden 方法在接受迭代之后进行缩放坐标下的秩一更新，并在周期到期、下降不足、矩阵退化或近似矩阵不能给出可接受步时重新差分。差分探针与拒绝步不画成已接受迭代。矩阵不跨独立求解或参数身份不同的模式复用。算法借鉴的是可审计的缩放、全局化和矩阵更新机制，并非复制 ROCETS 的完整执行处理器。

`solve_nonlinear` 的 `residual_scales` 控制数值归一化，`residual_tolerances` 定义各方程原始单位下的绝对验收容差。显式传入后，改变数值尺度不会改变验收阈值；旧调用未指定时仍使用 `residual_scales * tol`，保持兼容。小步长、目标函数停滞或信赖域程序返回成功都不能代替逐项残差通过。独立的系统守恒和工程约束仍须单独验收。

发动机适配层当前保留原有验收数值：绝对功率容差仍由该次初始泵功率尺度生成，再显式交给求解器。因此，通用求解器已能将缩放与验收分开，但发动机侧尚未定义与初猜完全无关的统一工程功率容差；不能将本次改动解释为任意初猜下阈值完全不变或工作点唯一性已获证明。

`variable_scales`、`diff_steps` 和 `max_steps` 分别表示变量尺度、物理单位下的差分步长和每轮允许的最大变量变化。差分会记录实际采用的探针，边界处采用可行方向。牛顿法和 Broyden 方法支持逐变量限步，再进行回溯；信赖域方法使用自身步长管理，不支持这一显式限步参数，传入会报错。变量上下界与限步并不能证明处于多维部件特性图适用域内，适用域仍由具体模型声明和校核。

新计算记录的“收敛诊断”包含：

- 每个方程的原始残差、数值尺度、绝对容差及所属部件；曲线用残差与验收容差之比表示时，以 1 为达标线。
- 变量名称、单位、尺度、差分步长、限步和边界信息。
- 完整雅可比重建次数、近似更新次数、全部模型调用次数、求解耗时，以及步长缩减原因。
- 模型求值失败的阶段、可识别的变量或部件、错误信息和试探状态。失败试探不覆盖最后接受的工作点。
- 缩放雅可比的数值秩、条件数及相关方程、弱敏感变量提示。它们只描述所记录点和当前差分精度下的局部性质，不能证明全局唯一性，也不能单独判定物理无解。

这些诊断在计算结束后由保存的实际轨迹生成，不是实时动画。历史记录缺少新字段时显示未记录，不补造零次更新、零次失败或完整适用域证据。完整重建次数仅统计完成的矩阵，重建尝试次数和失败求值另行保留。

运行可复现的三方法对照：

```powershell
.\.venv-web\Scripts\python.exe -X utf8 scripts\benchmark_nonlinear.py --repeats 3
```

输出为 `diagnostics/nonlinear_benchmark.json`，包含不同初猜、单位变换、相关方程、弯曲残差和适用域错误等解析算例。每个方法使用相同的方程、初猜、上下界、验收容差与求值预算，调用次数包含差分、拒绝和失败试探，耗时报告重复运行中位数。该报告只检验通用数值行为；真实发动机是否加速，必须在同一模型、同一边界及相同物理验收标准下另外对照，不能由解析算例外推。
