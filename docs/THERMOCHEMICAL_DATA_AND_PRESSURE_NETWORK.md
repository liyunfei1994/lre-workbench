# 甲烷热化学数据与压力网络定义修正

日期：2026-10-23。适用范围：现有集总稳态循环、参数编辑器和结果追溯。没有调整压降预算来匹配推力或比冲，没有加入 CFD / FEA。

## 1. 可替代 GRI30 的数据

上一轮遗漏了本机 Cantera 3.2 随附的 `gri30_highT.yaml`。本轮直接核对了安装文件，而非只根据文件名判断。

| 数据 | 核实结果 | 本平台用途 |
|---|---|---|
| `gri30.yaml` | 53 物种，全部物种共同温区 300–3000 K；主要燃烧产物上限多为 3500 K | 历史方案和对照 |
| `gri30_highT.yaml` | 同名同顺序 53 物种；28 物种热系数变化；全部物种共同温区 300–5000 K；主要产物可到 6000 K | 新增甲烷稳态热化学选择，新载入 Raptor 类示例采用它 |
| `nasa_gas.yaml` | 748 物种数据，111 个中性 CHO 物种；没有可直接替代整机的完整相定义 | 继续用于明确物种集合的独立对照，当前已有 CHO16 候选 |
| `nDodecane_Reitz.yaml` | 正十二烷替代机制，含理想气与 RK 相；共同温区上限仍为 3000 K | 不替代甲烷数据 |
| `airNASA9.yaml` | 空气体系，不覆盖完整甲烷燃烧物种 | 不直接用于液氧/甲烷循环 |

`gri30_highT.yaml` 文件说明为 Joseph Shepherd 基于 NASA TM-4513 增加高温多项式，仍是 ideal-gas 相。53 个物种和 325 条反应方程与原版一致，但本稳态模型调用平衡，不借此认证高温高压有限速率动力学。

来源：[Cantera 3.2.0 高温文件](https://raw.githubusercontent.com/Cantera/cantera/v3.2.0/data/gri30_highT.yaml)、[NASA TM-4513](https://ntrs.nasa.gov/citations/19940013151)、[NASA gas 数据文件](https://raw.githubusercontent.com/Cantera/cantera/v3.2.0/data/nasa_gas.yaml)、[Cantera 物种热力学](https://www.cantera.org/stable/reference/thermo/species-thermo.html)。

NASA gas 不能按化学式自动替换：CH₂ 与 CH₂(S) 电子态不同，多个含碳物种存在异构体。更多物种或更高阶多项式不自动等于更准确。

## 2. 程序与历史兼容

- 新输入 `methane_thermo_dataset` 可选 `gri30` / `gri30_highT`。缺失字段的旧方案仍按 `gri30` 解释；不改用户已保存输入和结果。

- 同一选择贯通推进剂化学焓参考、预燃室、主室、涡轮、喷管和最终温区检查；气体状态记录数据文件身份，防止离开计算作用域后被旧数据重建。
- 可变 Cantera 对象按数据集、工质和线程隔离；异常退出后恢复原作用域。
- 计算环境和界面保存实际文件、版本、SHA-256、物种数量及温区。共同温区与逐态所含物种温区分开显示。
- 校核请求继承来源记录的数据选择；不会把高温版整机记录悄悄用原版 GRI30 对照。
- 高温数据仍不包含凝聚碳/积碳输运，不解决高压燃气非理想性。富燃工况的相稳定性、产物集合充分性需另行验证。

## 4. CEA 条件一致的对照

另运行 18 对实际 Cantera / RocketCEA 计算：压力 10 / 33 MPa、O/F 3.2 / 3.6 / 4.0、面积比 34.34，连续平衡/主室冻结/喉部冻结三种口径。两端使用相同入口焓、元素原子量和共同 CHO16 气相集合。

18 对均返回有效结果，Cantera 保存截面均在所选数据温区内。相对差异最大值：主室温度约 0.10768%、c* 约 0.03980%、真空比冲约 0.05081%。这是两套计算的差异，不是与试验的误差，也不是规定的合格阈值。

33 MPa、O/F=3.6、主室冻结的受限基准：Cantera 3777.669 K / 346.6426 s；CEA 3774.301 K / 346.4989 s。此处是独立燃烧室/理想喷管，不是包含泵、涡轮、冷却的 FFSC 整机。两端均理想气体，不能验证高压 EOS；CHO16 不能验证极富燃预燃室或积碳。

## 5. 压力网络的数值身份

现有四支路方程已经在每次循环求解中反馈所需泵压和轴功，本轮没有为了修标签重写这套方程。输入默认数值也未改变。

| 参数 | 数值身份 | 分母 / 作用位置 |
|---|---|---|
| 0.12 | 指定设计压降预算 | 各支路目的预燃室压力 pPB；四条供给支路 |
| 0.243 / 0.093 | 两股热气的指定压降预算 | 主室 pc；涡轮出口至主室，不是液路主喷注 |
| 0.03 | 基础管路/全开阀损失预算 | 主室 pc；另求的附加调节损失分列 |
| 5 MPa | 给定模式的冷却总压降预算 | 燃料主泵后、分流取流点之前；直接改变所需泵压 |

这些数值没有足够的 Raptor 3 原文、页码、测点与工况证据，统一标识为未核实工程假设。不能用另一机型的文献或一般公式为这些特定数值背书。

真实模型涡轮压比为 πT=pT,in/pT,out。本模型把预燃室出口直接当涡轮入口，未另计中间管损；涡轮出口压力还需支付热气至主室的预算，因此 πT 与 pPB/pc 不同。内部采用忽略宏观动能变化的集总绝对压力，尚未分别解析每个截面的总压和静压，不能无条件解释成实机总压压比。

本轮高温版额定点：

| 输出 | 氧侧 | 燃料侧 |
|---|---:|---:|
| πT | 1.499756 | 1.646644 |
| pPB/pc | 1.864196 | 1.799782 |
| 最低所需泵出口压力 / MPa | 69.890692 | 74.890692 |
| 固定泵可用出口压力 | 未验证 | 未验证 |

模型拓扑为全部燃料先冷却再分流、氧化剂在主泵后分流。最低供给压力由同一取流点最苛刻支路决定，其他支路通过附加调节压降满足预算。附加阀压降不是已证明的泵压储备。

## 6. 修复的压力显示问题与新增检查

固定支路阻力计算时，实际压降使用保存的 K、当前流量和密度；旧 `injector_dp_ox_MPa` / `injector_dp_fuel_MPa` / `valve_line_dp_MPa` 汇总仍按设计比例计算。它们不是四条支路在当前工况的实际损失。

现在明确标记上述旧键为兼容设计预算，界面以逐支路实际值为准。基础损失、喷注损失、附加阀损分列，避免重复扣除。

新增保存的压力定义与独立复核证据：

- 两股热气入口/出口/主室压力、πT、pPB/pc、实际压降、指定预算及残差。
- 主泵最低所需出口压力、模型出口压力、压升、冷却压降及相互一致性。
- 四支路取流点、预燃室、支路出口与保存流体状态交叉核对。
- 中间压力节点由本次集总损失分配记录，不冒充实物测点。
- 压力方程闭合与部件能力验证独立显示。没有泵扬程—流量/效率图、涡轮流通图和阀门特性时，固定硬件能力仍为 `not_verified`。
- 固定阻力扫描只冻结四支路阻力；热气段仍沿用压降比例预算，不能称作完整固定整机节流包线。
- 历史结果缺失的证据显示“未记录”，不按新输入补算。

本轮针对科学计算的 197 项回归测试、360 项 JavaScript 测试均通过；网页后端全量检查首次有两项旧预设断言与新显式高温选择不符，已更新并定向复核。新数据身份测试包括作用域恢复、不同线程隔离、GasState 跨作用域重建和入口焓正反求。

## 8. 后续复核：热化学接口与统一冷却模型

同日后续应用户请求进行只读代码审计与独立诊断。本节不表示这些问题已经修复，也不改变前述历史计算的输入。新增诊断文件位于 `diagnostics/thermo_cooling_reaudit_20261023/`，不修改生产方案、数据库或计算算法。

### 8.1 热化学仍需处理的内容

1. **纯流体适用性检查缺口（优先）。** 当前燃气多项式检查不覆盖纯流体 EOS/输运模型温压范围及液体泵入口相态。`thermo.py:187–202,228–257`、`cooling.py:124–142` 依赖库调用成功；`pump.py:242–249` 仅为正十二烷检查相态。本机 HEOS 给出 Methane Tmax=625 K、Oxygen Pmax=80 MPa；一些超界查询仍返回有限数值。需要逐冷却单元检查 bulk 与近壁物性，并区分数据范围、相态与相关式适用性。当前正常低温贮箱边界不因此自动判错。
2. **组成接口防错缺口。** `thermo.py:960–979` 在甲烷路径丢弃未知物种后归一化，空组成改用纯 N2，未拒绝负值。正常闭环本轮未发现触发；但导入/重建状态时可能改变元素与质量，应统一拒绝无效组成并只允许小的归一化舍入误差。
3. **参考点残余焓近似。** `thermo.py:190–202,245–248,1250–1262` 将化学理想气焓与 298.15 K / 1 atm 的 HEOS 焓直接对齐，未补参考点残余焓。本机 CH4、O2 残余焓分别约 −989.145、−250.229 J/kg；相对于理想气体极限锚定，当前输入焓偏高相应数值。O/F=3.6 时混合偏移约 410.86 J/kg。此量不证明性能误差很大；修正应同时覆盖正算、反算、CEA 输入和 reference_id。
4. **高压混合气与产物集合仍需验证。** 温区覆盖不验证气相 EOS、预燃室近平衡假设、富燃凝聚相稳定性或冻结涡轮假设。优先研究较低温的高压预燃室/涡轮工况；不能只更改 YAML 的 EOS 名称。
5. **热侧抽热位置是显式近似。** `cycle.py:772` 将包括喷管段的总冷却热量集中在主室扣除，再做绝热冻结喷管。全机总账可闭合，但热侧空间位置不闭合。冷侧准一维升级不能自动消除这个近似。
6. **冷却气侧输运物性未随 YAML 自动升级。** `cooling.py:189–209` 用当前 gamma/M 推出 cp，黏度取 3000 K 参考值的 T^0.7 幂律，Pr 用 Eucken 近似；并非逐节点按所选组成计算输运性质。旧注释的“NIST 拟合”没有附原始来源，需补证或降格为经验假设。采用 Cantera 输运计算也需另外验证其高压与温区适用性，不能只因来自同一库就默认更准确。

另外，桌面热化学对照调用没有传入所选数据集，可能退回原 GRI30；网页来源绑定已正确。私有旧对照包装函数缺少新请求字段。两者应在接口清理时同步处理，避免旧入口失配。

物性范围依据：[CoolProp Methane](https://coolprop.org/fluid_properties/fluids/Methane.html)。实际数值以本机版本查询为准，EOS 界限不等同于所有输运关联式都已验证的界限。气相模型依据：[Cantera 相模型](https://www.cantera.org/stable/reference/thermo/phase-thermo.html)。

### 8.2 冷却现状及实际差异

网页 `webapp/solver.py:154–155` 明确关闭 `include_cooling_marching`；主循环使用 `CoolingChannel` 的分区热积分/代表状态水力。旧沿程模型仅在桌面或显式后处理运行，未反馈主循环。网页当前没有冷却沿程曲线入口。

复用第 3 节保存的高温额定点，冻结边界后实际运行旧沿程模型：

| 指标 | 主循环 | 旧沿程后处理 |
|---|---:|---:|
| 吸热量 / MW | 135.145589 | 112.783510 |
| 采用或计算压降 / MPa | 5.000000（给定） | 22.211173 |
| 冷却剂出口温度 / K | 385.420272 | 340.280614 |

### 8.4 已运行的独立极限检查

`probe_cooling_limits.py/.json` 使用隔离的常物性/无摩擦极限与零热量工况；这些是诊断，不是新的发动机预测。

- 无热、无摩擦、常密度而通道变截面：旧模型给出全程零静压变化；按相同站点速度的 Bernoulli 极限需要约 16.65 kPa 端点静压差。证明仅有密度变化项不足以描述现有变截面几何。
- 真实甲烷零热量、有压降的恒截面诊断：旧模型始终保持 300 K；按其忽略动能的静焓账反求应为约 301.183 K，账差约 −11.37 kW。即使细化热步长，缺少压力对温度的影响也不会自动消失。
- 本机 Methane 声明 Tmax=625 K，但 650 K、750 K / 60 MPa 查询仍成功，说明需要主动适用性守卫。

`probe_thermo_contracts.py/.json` 另外复现参考焓偏移、组成防错缺口、超界查询和气态泵入口被接受的情况。所检查正常高温版额定点的 9 个纯推进剂端口均在声明温压范围内；这些异常探针不代表当前正常端口已经越界，也不覆盖所有沿程近壁状态。

### 8.5 建议的统一系统模型与验收

1. **先统一几何和端口。** 一个不可变几何对象包含实际内轮廓、冷却覆盖、冷却剂流向、通道数/宽/高/壁厚、弧长、局部阻力所在节点。主喷管喉面积不得在冷却器内另行独立估算。设计定尺寸与固定硬件工况计算分开。
2. **冷侧沿程守恒。** 无旁路时每单元 mdot 相同；用质量、动量及能量守恒解 p、h、u。若保留速度效应，采用 h0=h+u²/2，满足 mdot·Δh0=ΔQ；忽略动能时应给出量级检查。局部阻力使用对应位置状态；通道分叉/合并作为节点处理。
3. **热端同源。** 每个单元同时给出气侧/壁内/冷侧热流一致性。Bartz 是气侧换热关联式，不单独决定总Q；相关式范围、壁材导热和辐射假设要记录。若覆盖喷管，逐段热量应反馈对应燃气能量方程。若先保留主室集中抽热，界面必须继续标“冷侧准一维、热侧集中等效”。
4. **唯一输出。** 返回 Q、dp、出口p/h/T，以及边界节点和单元剖面、各项残差、数据范围、失败位置。主循环、卡片、曲线、导出全部消费这一份结果；不再分别运行两套冷却算法。
5. **外环耦合。** 泵出口/燃气边界变化后更新冷却，冷却出口反馈四供给支路和主室；验收同时检查Q、dp、出口焓和内层残差，不能仅检查温度变化。
6. **保留给定预算模式。** 有来源的Q/dp预算仍可用于初步设计。该模式不伪造沿程曲线，不宣称固定硬件预测；自动水力模式与给定模式互斥。
7. **验收先于包线。** 零热量、无摩擦变截面、常物性解析解、局部损失端点、正逆流、分支质量/元素账、网格加密、失败状态、部件/整机端口一致性、固定几何节流。再比较额定点和节流，不能按目标Isp调关联式系数。

建议顺序：纯流体守卫与组成接口 → 参考焓一致性 → 统一冷却几何/守恒内核 → 热端位置与主循环耦合 → 单一数据源曲线 → 固定硬件复算。高压EOS与产物相稳定性作为独立验证任务推进。系统级一维热流/壁温/冷却流体联合计算有既有研究基础，参见 [NASA：Wall temperature distribution calculation for a rocket nozzle contour](https://ntrs.nasa.gov/citations/19720023123)；这不替代本平台自己的验证。
