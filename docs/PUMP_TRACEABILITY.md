# 泵几何与稳态设计交接追溯

Web 概念设计任务完成时，以该任务保存的 `project_id / revision / record_id / mode`
绑定泵子午面快照，并在结果中保存 `design_traceability`。方案当前草稿不参与记录读取或导出。

追溯链保存三份有明确含义的输入：任务提交输入、求解入口归一化输入和循环实际计算输入。
后者可能含求解得到的设计变量，不要求三者完全相同。另保存稳态审查门卡、两侧泵输出，
以及输入、完整 calculation、泵输出、稳态报告和两侧几何的 SHA-256。
摘要用于检测证据变化，不是数字签名，也不是工程验收结论。

读取 `/api/jobs/{id}` 时，服务端对照任务身份和保存证据生成只读审计，并将共同追溯信息
附在 `pump_geometry.traceability` 与 `steady_design.traceability`。接口保留原始 `result`，
不回写数据库、不重新求解、不按最新默认值重建历史几何。

- `verified`：完成时保存的证据与当前记录一致。
- `legacy`：旧记录缺少完成时的追溯证据，仅从该记录投影，明确提示证据未冻结。
- `conflict`：方案、版本、记录或证据不一致；稳态交接标记阻塞，两侧泵停止导出。

泵快照已有非空来源时，不能用另一个记录 ID 或方案身份覆盖。没有来源的历史快照允许
在读取时绑定其所属任务，但不会因此升级为 `verified`。保存坐标和几何假设发生冲突时，
保留可检查的冻结坐标并停止交接，不用当前输入替换坐标。

前端只接受当前方案、当前读取序号下的同一记录响应；切换方案会使此前的读取失效。
任务列表、记录读取和运行提交也执行方案归属核对，避免迟到响应污染新方案。

CAD 坐标继续以保存的子午面坐标为唯一来源，单位为 m。JSON 包含追溯链；其他格式
随下载提供追溯 JSON 清单，记录文件名、文件内容摘要、输入/稳态证据摘要、几何摘要和方法假设。
TXT 保留无表头两列坐标，便于专业软件导入。导出文件与其追溯清单应共同归档。
这些文件是概念代表级参考边界，不能替代叶片、诱导轮、汽蚀、结构或制造验证。

回归入口：`web_tests/test_design_traceability.py`、`test_pump_geometry.py`、
`test_pump_geometry_integration.py`、`test_pump_geometry.mjs` 和 `test_steady_design.mjs`。
