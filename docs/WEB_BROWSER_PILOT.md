# 校外浏览器试用

测试人员打开 HTTPS 网址，直接用管理员分配的工作台个人账号登录，修改自己的计算参数并运行计算。
试用入口采用“HTTPS + 工作台个人账号”，不经过邮箱验证码入口，也不开放自行注册。
Python、Cantera、CoolProp 和任务队列仍运行在平台主机；测试人员不安装这些软件，也没有修改服务器程序的接口。
连接工具仅安装在主机。主机必须开机、联网且不休眠。

## 部署后的入口验收

登录页可以公开访问；项目、结果和计算接口由工作台账号与项目归属控制。每次部署或调整入口后，重新完成以下检查，不沿用另一台主机或旧入口的验收结论：

1. 使用独立浏览器会话打开 HTTPS 地址，确认首页与脚本正常加载，刷新后仍进入工作台账号登录页。
2. 在未登录状态访问项目、任务和成员接口，确认返回 JSON 401；使用无效测试凭据确认错误密码提示可见，不在日志、文档或截图中保存真实密码。
3. 使用独立普通测试账号登录、刷新、创建方案、运行计算并导出结果，再核对下文的账号隔离和权限清单。
4. 如测试密码修改，使用专门的测试账号确认旧会话失效、旧密码被拒绝、新密码可登录。
5. 从校外网络重复正常用户流程，记录部署版本、时间和通过／未通过项。匿名入口检查通过不代表登录、计算和跨校访问已全部验收。

本文提供部署与验收步骤，不声明某个入口已上线或通过验收。实际状态以本次部署的进程和检查结果为准。

## 权限与数据

| 操作 | 普通使用者 | 管理员 |
|---|---|---|
| 从工程示例创建自己的方案 | 可以 | 可以 |
| 调整自己的参数、提交计算、查看和导出自己的结果 | 可以 | 可以 |
| 读取或覆盖其他账号的方案、历史版本和结果 | 不可以 | 可以 |
| 创建账号 | 不可以 | 可以 |

项目归属取自不可变的第 1 版作者。管理员帮助修订方案，不会改变归属。
私有模式写入数据库，后续省略 `--private-workspace` 也不会退回全员共享模式。
管理员的原始方案默认不向普通账号展示；普通账号可以从平台自带工程示例开始。

原有 `start_web_windows.bat` 启动 8765 本机个人工作区，仅原管理员使用，不再提供成员管理。
校外成员仍在 8766 试用工作区管理；两个工作区的账号和数据相互独立。
试用使用独立目录 `user_data/browser-pilot/` 和端口 8766，不复制研究数据库、账号或结果。

## 1. 在本机初始化

双击根目录 `start_web_pilot_windows.bat`，浏览器进入本机 8766 页面。

1. 首次使用时创建试用工作区管理员；已有管理员直接登录，不重复创建。
2. 需要更换密码时，点击右上角“修改密码”，填写当前密码、新密码及确认密码。新密码必填，最多 128 位；修改成功会撤销本账号在所有设备上的会话，须用新密码重新登录。密码不写入源码、Git、聊天或截图。
3. 在“成员管理”为测试人员创建普通账号，每人使用自己的用户名和密码。新建管理员、创建成员及修改密码统一要求非空、最多 128 位；已有账号仍可使用原密码登录。不要共用管理员账号。
4. 完成本机验证后，在该试用服务窗口按 Ctrl+C 停止 8766；保留原有 8765 服务。

此时尚未建立校外入口。`start_web_pilot_windows.bat` 仅用于本机初始化，不能恢复公网入口。
远程模式拒绝启动未初始化的数据库，并禁用首次管理员创建接口。

## 2. 建立临时 HTTPS 入口

小范围测试可用 Cloudflare Quick Tunnel，无需准备自有域名。
仅在主机上从 [Cloudflare 官方下载页](https://developers.cloudflare.com/cloudflare-one/networks/connectors/cloudflare-tunnel/downloads/)安装 `cloudflared`；测试人员只使用浏览器。
以下命令采用工作台账号模式，不附加 `--allowed-mail`：

```powershell
cloudflared tunnel --url http://127.0.0.1:8766
```

保持进程运行，记下它实际返回的 `https://...trycloudflare.com` 网址。
后端此时尚未启动，入口暂时不能使用。不要把目标改成研究工作区的 8765，也不要用 `--http-host-header` 改写 Host。

在项目根目录另开 PowerShell，把以下域名替换成实际返回的网址：

```powershell
.\.venv-web\Scripts\python.exe -m webapp.run --port 8766 --database user_data/browser-pilot/workspace.sqlite3 --private-workspace --public-origin https://实际返回的域名.trycloudflare.com --open-browser
```

`--public-origin` 仅接受单个明确 HTTPS 域名。服务继续绑定回环地址，不开放公网监听端口。
代理必须保留外部 Host 并设置 `X-Forwarded-Proto: https`。本应用不启用 Uvicorn 的通用代理头信任。
Cookie 使用 Secure、HttpOnly、SameSite=Strict；写操作核对配置的 HTTPS Origin。
登录按账号和整体预算限制，不依赖任意传入的 IP 请求头。

若网络阻断 QUIC，可在上述隧道命令中添加 `--protocol http2`。若申请网址时连接 `api.trycloudflare.com` 超时，应先检查主机的出站网络和代理；拿到网址后仍须看到隧道连接成功，不能仅凭分配了网址就判断可用。不要把研究服务改成公网监听来处理连接失败。

此前本机的入口申请需要经过现有 HTTP 代理，并使用 HTTP/2 建立隧道。这属于本机网络配置，不保存在项目源码中；通用启动命令不保证在该网络下直接成功。重新启动隧道后，须把新网址同步到后端 `--public-origin`，并重新验收。

## 3. 验收后发放网址

先用外部网络（如手机移动数据）实测，再交给校外人员：

- 首页直接显示工作台账号登录，不再要求邮箱验证码；未经登录不能读取项目、结果或提交计算。
- 管理员分配的账号能够登录，错误密码被拒绝；登录后刷新仍可使用工作台。
- 普通账号看到“我的项目”，可创建方案、运行设计点并下载自己的结果。
- 两个普通账号互相看不到对方项目，直接访问对方记录链接也被拒绝。
- 普通账号不能管理成员、取消别人的任务或覆盖管理员原始方案。
- 修改自己的密码后，本账号原有会话失效，旧密码不能登录，新密码可以登录。
- 原有 8765 工作区和研究数据正常。

隧道服务在各校网络中的可达性须现场验证，代码测试不代替跨校验收。
队列仍是每工作区一次一个计算任务，每账号最多 3 个等待/运行任务，全工作区最多 12 个。

通过验收后，管理员把最新地址及个人账号分别交给对应测试人员。测试人员的使用顺序为：

1. 在浏览器打开管理员提供的 HTTPS 平台首页，不使用 `127.0.0.1` 本机地址或旧邮箱验证链接。
2. 输入自己的工作台用户名和密码。
3. 在“我的项目”中新建方案，载入工程示例、调整参数并运行设计点。
4. 查看计算状态和结果，保存方案或导出自己的结果。使用结束后退出账号。

管理员只需事先创建账号，不需要逐次批准登录。测试人员无需接触服务器代码或安装计算软件。

## 停止及后续

停止 `cloudflared` 后公网入口失效；再用 Ctrl+C 停止试用计算服务。
也可从项目根目录请求停止试用服务：

```powershell
New-Item -ItemType File -Path user_data/browser-pilot/stop.request -Force
```

退出账号不会删除服务端数据。备份运行中的试用数据库应使用 SQLite 在线备份，不能只复制主数据库文件。
当前网页支持验证当前密码后修改自己的密码，尚无密码找回和账号停用功能。需立即收回整个入口时先停止隧道。

Quick Tunnel 的网址每次启动改变、没有在线率保证、不支持 SSE，最多 200 个同时未完成请求；平台目前通过轮询读取任务进度。
长期使用应配置固定域名、受控入口和持续运行的主机，保持相同的账号与项目隔离机制。

官方依据：[Quick Tunnels](https://developers.cloudflare.com/tunnel/get-started/quick-tunnels/)。本文为配置与验收说明；当前是否在线，应以进程状态和实际浏览器访问为准。
